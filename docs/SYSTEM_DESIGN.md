# 第一部分：系统框架设计说明（论文 §5.4 实验平台描述的依据）

## 1. 系统定位

本系统是硕士学位论文《Y企业混合流水车间生产计划与调度反馈集成优化研究》的**实验平台与决策支持原型**，不是商用 MES。系统实现论文第 3–5 章的滚动时域闭环集成优化机制，支持：

- 导入企业生产信息（产品、需求、成本、产能）与车间信息（阶段、机器、工人技能、SDST 矩阵）；
- 运行"计划层—调度层—反馈层—滚动更新"闭环，输出各滚动周期冻结后的生产计划与调度方案；
- 支撑论文 §5.5 的方案 A–D 对比实验、反馈通道消融实验与权重敏感性分析。

## 2. 五层架构

```
┌─────────────────────────────────────────────────────────┐
│  L5 实验与报告层  ExperimentRunner / Reporter            │
│      方案A–D对比 · 通道消融 · 敏感性分析 · Excel/图表导出  │
├─────────────────────────────────────────────────────────┤
│  L4 滚动控制层  RollingController                        │
│      滚动窗口H_w · 冻结长度H_f · 反馈迭代k · 终止条件      │
│      状态滚动更新：库存/欠交/未完成订单                    │
├──────────────────────────┬──────────────────────────────┤
│  L2 计划层                │  L3 调度层                    │
│  PlanningModel (MILP)     │  SchedulerAdapter             │
│  q_plan, Y_plan, Inv,     │  ├ ExactScheduler (CP-SAT)    │
│  Back, OT, 有效产能约束,   │  └ MetaScheduler              │
│  不可行组合割, 风险惩罚项   │    (vendor_nsga/ 真实         │
│                           │     NSGA-II-VNS-MOSA)         │
├──────────────────────────┴──────────────────────────────┤
│  L2.5 反馈层  FeedbackBuilder（三通道，各带独立开关）      │
│      ① 成本修正 Δc  ② 有效产能 Cap_eff  ③ 不可行组合割 ΔH │
│      代表解选择 π* · 保护处理（式3-9：正库存先冲抵欠交）    │
├─────────────────────────────────────────────────────────┤
│  L1 数据层  ProblemData + ExcelAdapter                   │
│      V-toy-1 工作簿（金标回归） · Y企业数据模板 · 示例数据  │
└─────────────────────────────────────────────────────────┘
```

## 3. 数据流（单个滚动周期 τ 内）

1. `ExcelAdapter` 读入数据 → 构造 `ProblemData`；
2. `RollingController` 取当前窗口需求，令 k=1；
3. `PlanningModel` 求解 MILP → q_plan, Y_plan；
4. 子批化映射：q_plan → 调度工件集合 I_sch；
5. `SchedulerAdapter` 求解 HFSP-SDST → Pareto 解集 → 代表解 π*；
6. `FeedbackBuilder` 折算三通道反馈向量 F_τ^{sch,raw,(k)}；
7. 未收敛且 k < K_max → k+1 回到步骤 3；否则冻结本周期方案；
8. 保护处理与状态更新（库存、欠交按式 3-9 口径）→ τ+1。

## 2. 论文机制与符号（实现必须与之对齐）

### 2.1 分层机制

- **计划层**：滚动时域 MILP。决策变量：生产量 $q_{p,t}^{\mathrm{plan}}$、启动变量 $Y_{p,t}^{\mathrm{plan}}$、库存 $\overline{Inv}$、欠交 $\overline{Back}$、加班 $OT$。含需求平衡、产能（含有效产能反馈）、启动逻辑、不可行组合割、调度风险惩罚项。
- **调度层**：HFSP-SDST，多技能工人、技能—速度耦合、向下兼容，三目标 $C_{\max}$ / $LC$ / $E$。两个求解器：CP-SAT 精确求解器（小规模验证）与 vendor_nsga 元启发式（正式实验）。
- **反馈层**：三通道结构化反馈，统一记号 $F_\tau^{\mathrm{sch,raw},(k)}$（滚动周期下标 $\tau$、反馈迭代上标 $(k)$）：
  ① 成本修正 $\Delta c$（真实调度成本与计划层估计的差额，修正计划层目标函数）；
  ② 有效产能 $Cap^{\mathrm{eff}}$（由代表解折算，收紧计划层产能约束）；
  ③ 不可行组合割 $\Delta\mathcal{H}$（结构性不可行的产品组合，加入割约束）。
  代表解 $\pi^*$ 按归一化加权准则从 Pareto 解集中选取。
- **滚动更新**：冻结长度内方案锁定；保护处理按论文式 (3-9)：**欠交累计前必须先用正库存冲抵**，禁止直接累加欠交。
- **索引纪律**：周期索引 $t$ 与滚动周期 $\tau$ 严格区分，代码变量命名同样区分（如 `t` vs `tau`）。

### 2.2 三步割生成判据的守卫（重要）

论文 §5.2.1 的三步不可行判据需加"加班型排除"守卫：**仅当加班超上限（$OT > OT^{\max}$，即 $\rho = 0$）时才生成不可行组合割**；加班可覆盖（上限内）的不可行不生成割，只走加班/成本通道。V-toy-1 中预期行为：$\tau=1$（加班型，上限内）**不触发**割；$\tau=3$（结构性组合冲突超上限）**触发**割。若现有代码与此不符，以此为准修正，并用 V-toy-1 数值验证。
